# 贡献指南 / Contributing

> 适用范围：**未必科幻压缩引擎**（MBSF Compression Engine）及其公开包 `@mbsf/core`、`mbsf-compaction`。

---

## 中文

### 本项目不接 PR

**只收 issue（问题报告 / 功能建议），不接受外部代码合并（Pull Request）。**

原因：

1. **版权干净**——本项目的作者只有一人（单人版权）。接受代码贡献会引入「共同作者」关系，将来在商业许可、专利、再分发上产生不必要的法律复杂度。
2. **无维护承诺**——不接 PR 就不欠任何人「我会合并 / 我会维护你的改动」的承诺。
3. **专利风险**——贡献者带来的代码可能涉及第三方专利，单人项目没有能力做专利尽调。

### 欢迎什么

- **Bug 报告**：复现步骤、环境版本、期望行为
- **功能建议**：使用场景、你希望它解决什么问题
- **文档纠错**：错别字、过时说明
- **安全漏洞**：**请不要公开提 issue**，发邮件到 copyright@weibikehuan.cn

### 提交 issue 的格式

```
环境：DSH 版本 / 包版本 / 操作系统
复现：1. … 2. … 3. …
期望：
实际：
其他：
```

### 将来会接 PR 吗

如果项目需要长期外部贡献，会另行发布 CLA（贡献者许可协议）后再开放。在那之前，**请只提 issue**。

## English

### No pull requests

**This project accepts issues only — no external code contributions (pull requests).**

Why:

1. **Clean copyright** — the project has a single author. Accepting code contributions would create co-authorship, adding legal complexity for commercial licensing, patents, and redistribution.
2. **No maintenance promise** — no PRs means no obligation to merge or maintain your changes.
3. **Patent risk** — contributed code may carry third-party patent exposure; a single-author project cannot do patent due diligence.

### What is welcome

- **Bug reports**: reproduction steps, environment versions, expected behavior
- **Feature requests**: use cases, the problem you want solved
- **Documentation fixes**: typos, outdated descriptions
- **Security vulnerabilities**: **do not open a public issue** — email copyright@weibikehuan.cn

### Issue format

```
Environment: DSH version / package version / OS
Steps: 1. … 2. … 3. …
Expected:
Actual:
Other:
```

### Will PRs ever be accepted?

If the project later needs long-term external contributions, a CLA (Contributor License Agreement) will be published first and PRs opened then. Until then, **issues only**.
